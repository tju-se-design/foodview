# 食见 FoodView

> 面向高校的校园餐饮信息服务平台，以单道菜品为中心，把食堂和档口的菜品、价格、供应状态与学生反馈集中到一处。

食见服务四类人：在校学生、食堂经营方、校方管理部门，以及临时进校的校外访客。学生在平台查某道菜今天哪个档口在做、什么价格、别人怎么评价；食堂能看到哪些问题被反复提出；校方拿到的是按食堂、档口、菜品和时间段聚合的反馈数据；访客在进校之前就能知道去哪个食堂、几点开门、大概花多少钱。

菜品信息分散在各食堂的公示栏和若干微信群里，反馈渠道同样分散，问题提了没人跟，跟了没有结果。食见把这些收进一个入口，并让每条反馈都能查到状态。

项目还在骨架阶段，业务表尚未建立。

## 功能

### 菜品数字档案

每道菜是一条独立记录，跨食堂、跨档口查询和对比：所属档口、价格、供应状态（在售、售罄、限时）、学生评价摘要。学生按菜名搜索，结果直接列出全校在做这道菜的档口，省掉先选食堂、再选楼层、最后找档口这几个步骤。

### 结构化反馈

评分拆成口味、价格、分量、供应、卫生五个维度，每条反馈可以打上问题类型（异物、分量不足、价格异常、排队过长等）。问题进入处理流程，学生在原处看到状态变化（已受理、处理中、已回复），处理结果回到同一条反馈上，不另开一页。

### 菜单共创

学生对现有菜品投票，也可以提新品建议。食堂试供新菜时收集一轮针对性反馈，试供结束后按投票和反馈生成菜品排名，作为排菜和调整供应的依据。

### 面向食堂与校方的数据

按食堂、档口、菜品、时间段聚合反馈量和需求趋势，用来判断哪些菜品该保留、哪些该调整供应时间、哪些问题反复出现。

### 访客就餐参考

食堂位置、开放时间、价格区间、菜品分布对校外访客开放，不需要注册即可查询。

## 技术栈

| 部分 | 选型 |
| --- | --- |
| 前端 | uni-app（Vue 3 + Vite + TypeScript），一套代码编译到 H5 与微信小程序 |
| 后端 | Spring Boot 4.1.2，Java 25，Maven |
| 持久层 | MyBatis-Plus 3.5.18 |
| 数据库 | MySQL 8.4（本地跑在 Docker 里） |

## 本地运行

需要 JDK 25、Node + pnpm、Docker。

```bash
docker compose up -d                      # MySQL，端口 3306
cd backend && mvn spring-boot:run         # 后端 8080，接口前缀 /api
cd frontend && pnpm install
cd frontend && pnpm dev:h5                # 浏览器 http://localhost:5173
```

健康检查：`curl http://localhost:8080/api/actuator/health`。

小程序端用 `cd frontend && pnpm dev:mp-weixin` 出产物，再用微信开发者工具打开 `frontend/dist/dev/mp-weixin`。
